# Pi 工作原理

> 中文译本，仅供学习参考，对应同目录的 `how-pi-works.md`。如与英文原文有出入，以原文为准。

Pi 负责协调模型请求、工具执行、上下文组装和会话存储。会话（session）是 Pi 对一次对话的记录，包含消息、工具调用与结果、模型切换、压缩（compaction）以及其他事件。

会话中的消息和事件构成一棵树。树上的每条路径都是一个分支（branch）。以当前条目结尾的分支是活跃分支（active branch），它提供下一次模型请求所需的历史。

## Agent 循环

提交的消息会被追加到活跃分支。Pi 依据系统提示词、活跃分支、可用工具和模型设置构造模型请求，然后通过选定的 provider 发送出去。

provider 以流式方式返回 assistant 响应，其中可能包含文本和工具调用。Pi 记录该响应，执行每个工具调用，并记录结果。至此完成一轮（turn）。如果工具结果或排队中的消息要求再次请求模型，Pi 就开始新的一轮；否则本次运行（run）结束。

Steering 消息在当前 assistant 轮次结束后进入。Follow-up 消息在 agent 完成所有待处理工作后进入。中止（abort）会停止当前运行，并把排队中的消息退回编辑器。

## 上下文

活跃分支提供对话历史。Pi 会把会话条目转换成模型可用的 user、assistant 和 tool-result 消息。

Pi 用基础指令和发现的上下文文件构造系统提示词。请求中还会带上工具定义和 skill 描述。

完整的 skill 指令按需加载。扩展（extension）可以添加指令或转换上下文。

Prompt 模板在编辑器输入变成 user 消息之前展开。选中的文件、图片、粘贴的文本和 shell 输出都可以成为消息内容。

## 会话

持久化会话是 JSONL 文件。每个树条目都有 ID，并指向其父条目。当前条目决定活跃分支。

从较早的条目继续，会在同一文件中创建另一个分支。Fork 和 clone 会把选中的历史复制到新的会话文件。

模型上下文由活跃分支重建。压缩会插入一条摘要条目，在后续模型请求中替代较早的消息。原始条目仍保留在会话树中。

## 界面

交互模式在终端中渲染会话事件和 agent 事件。Print 模式执行一个 prompt 并写出最终响应。JSON 模式以 JSONL 形式输出 agent 事件。

RPC 模式从 stdin 读取 JSONL 命令，向 stdout 写出响应和事件。TypeScript SDK 在进程内创建并控制 agent 会话。

所有界面共用同一套 agent 和会话机制。

## 扩展与资源

扩展是加载进 Pi 进程的 TypeScript 模块。其工厂函数用于注册工具、命令、快捷键、provider、事件处理器、渲染器和终端 UI。

Skills 提供按需加载的指令和配套文件。Prompt 模板提供可复用的消息文本。Themes 提供终端配色。Pi packages 通过 npm 或 git 分发这些资源。

## 信任与权限

Pi 在加载项目设置和资源之前先解析项目信任（project trust）。在信任决策和项目资源加载完成之后，Pi 加载上下文文件。启用的工具使用 Pi 进程的操作系统权限。扩展在同一个进程内执行。

## 译者注：术语对照

| 英文 | 中文 | 说明 |
|---|---|---|
| session | 会话 | 一次对话的完整记录，落盘为 JSONL 文件 |
| branch | 分支 | 会话树中从根到某个条目的路径 |
| active branch | 活跃分支 | 以当前条目结尾的分支，即下一次请求使用的历史 |
| turn | 轮次 | 一次模型响应加上由此触发的工具执行 |
| run | 运行 | 一次 `prompt()` 到 agent 停止的全过程，可能包含多轮 |
| compaction | 压缩 | 用摘要条目替代较早消息，原始条目仍保留 |
| steering | 引导消息 | 在当前 assistant 轮次结束后插入 |
| follow-up | 后续消息 | 在 agent 即将停止时插入 |
| provider | 服务提供方 | 模型 API 的接入方，如 OpenAI、Anthropic |
| extension | 扩展 | 加载进 Pi 进程的 TypeScript 模块 |
